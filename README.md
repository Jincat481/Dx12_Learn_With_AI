## 조작

프로그램을 켜면 **메뉴**가 먼저 뜬다. 스텝 하나가 항목 하나다. 고르면 그 씬으로 들어가고 `ESC` 로 돌아온다.
항목이 화면보다 많으면 스크롤된다 (휠 · ↑↓ · PageUp/Down · Home/End).

```
터레인 · 스텝 1  평면 그리드     격자 메시 생성 · 원근 카메라 · 깊이 버퍼 (S27~S35)
터레인 · 스텝 2  펄린 노이즈 지형  펄린 노이즈 fBm · 중앙 차분 법선 · 램버트 조명 (S36~S40)
터레인 · 스텝 3  높이맵 이미지 지형  회색조 이미지 → 높이 · 이중선형 보간 (S41~S43)
터레인 · 스텝 4  텍스처 스플래팅    경사도/높이 기반 4레이어 블렌딩 (S44~S47)
터레인 · 스텝 5  쿼드트리 컬링      청크 분할 · 절두체 평면 6장 (S48~S50)
터레인 · 스텝 6  거리 기반 LOD      거리에 따라 인덱스 간격 벌리기 (S51)
터레인 · 스텝 6-2 스티칭 & 지오모핑  스커트로 균열 메우기 · 모프 타깃 (S52~S53)
터레인 · 스텝 7  하드웨어 테셀레이션  성긴 패치를 GPU 가 실시간 분할 (S59~S62)
터레인 · 스텝 8  스카이맵           돔 + 방향 기반 하늘색 · 태양 (S54~S55)
터레인 · 스텝 9  동적 왜곡 구름     도메인 워핑으로 흐르는 구름 (S56~S57)
터레인 · 스텝 10 무한 지형 청크     카메라를 따라 청크 재활용 (S58)
터레인 에디터 · 지형 브러시      마우스 레이 피킹 · 브러시 편집 · 바뀐 청크만 재생성 · 저장 (S67~S70)
터레인 에디터 연결 · 바이옴      온도 · 습도 노이즈 → 바이옴 가중치 · 바이옴별 높이 식 (S73)
터레인 · 수력 침식              물방울 입자가 흙을 깎고 쌓아 계곡을 만든다 (S74~S75)
터레인 · 바다                  바람 스펙트럼 파도 · 게르스트너 · 흰 파도머리 · 반사 · 굴절 · 부딪히는 클릭 물결(파동 입자) · 폭포 · 진폭 보기 (S76~S90)
2D 스프라이트 데모               계층 Transform · 피킹 · 드래그 · Hierarchy / Inspector
종료
```

현재 들어가 있는 스텝은 창 제목에 표시된다.

| 입력 | 동작 |
| --- | --- |
| ↑ ↓ / 마우스 | 항목 이동 |
| Enter / 클릭 | 선택 |
| ESC (메뉴에서) | 종료 |

### 터레인 쇼케이스

카메라는 Unity 씬 뷰와 같은 **우클릭 프리룩** 방식이다. 오른쪽 버튼을 누르고 있는 동안에만 조작된다.

| 입력 | 동작 |
| --- | --- |
| **우클릭 + 마우스 이동** | 시점 회전 (좌우 무제한 · 상하 ±90도 제한) |
| **우클릭 + WASD** | 보는 방향으로 전진·후진 / 좌우 평행 이동 |
| **우클릭 + Q / E** | 아래 / 위로 이동 |
| **우클릭 + 휠** | 이동 속도 조절 |
| F | 기본 위치로 리셋 |
| **Tab** | **표시 모드 순환** — 텍스처 스플래팅 → 높이 색상 → 와이어프레임 → 평면 그리드 |
| N | 새 지형 생성 — 노이즈 지형은 새 seed, 높이맵 지형은 다음 이미지로 |
| P | 펄린 노이즈 ↔ 값 노이즈 전환 |
| C | 절두체 컬링 켜기/끄기 (스텝 5~) |
| L | 거리 LOD 켜기/끄기 (스텝 6~) |
| K | 스커트 켜기/끄기 (스텝 6-2) |
| M | 지오모핑 켜기/끄기 (스텝 6-2) |
| V | 구름 켜기/끄기 (스텝 8~9) |
| + / − | 구름 양 조절 |
| J | 무한 지형 켜기/끄기 (스텝 10) |
| **T** | **트라이플래너 매핑 켜기/끄기** (스플래팅 보기) |
| **O** | **거리 안개 켜기/끄기** (하늘이 있는 스텝 7~10) |
| **B** | **백그라운드 청크 생성 켜기/끄기** (스텝 10) |
| **G** | **비행 ↔ 걷기** — 걷기에서는 중력을 받고 땅 위에 선다 |
| **우클릭 + Space** | **점프** (걷기 모드) |
| **U** | **높이맵 생성 CPU ↔ GPU(컴퓨트 셰이더)** (스텝 7) |
| **R** | **높이맵 해상도 256 → 512 → 1024 → 2048** (스텝 7) |
| **Y** | **바이옴 켜기/끄기** (청크 지형). Tab 순환에 "바이옴 색상" 보기가 더해졌다 |
| **X** | **반사 패스 켜기/끄기** (물 표면) |
| **Z** | **굴절 · 깊이 켜기/끄기** (물 표면) |
| **[ / ]** | **수위 내리기 / 올리기** (물 표면) |
| **좌클릭 / 드래그** | **물결 일으키기** — 클릭한 수면에서 동심원이 퍼지고, 섬에 부딪히면 반사된다 (물 표면) |
| **3** | **바람 세기** 4 → 8 → 13 → 18 m/s — 파고와 주요 파장, 흰 파도머리 양이 함께 바뀐다 (바다) |
| **4** | **바람 방향 +45°** (바다) |
| **U** | **뾰족한 파도(게르스트너) 켜기/끄기** — 끄면 마루와 골이 똑같이 둥근 사인파 (바다) |
| **R** | **빗방울 켜기/끄기** (물 표면) |
| **1** | **물결 높이 보기** — 빨강 마루 · 파랑 골, 노랑은 물결이 반사되는 해안 벽 (물 표면) |
| **2** | **진폭 보기** — 오른쪽 아래 창에 물결 높이 텍스처를 그대로 띄우고 최대 진폭 · RMS · 커서 높이 · 단면 파형 · 감쇠 기록을 보여 준다. 창을 클릭하면 그 텍셀에 물방울 (물 표면) |
| **5** | **폭포 켜기/끄기** (폭포) |
| **6** | **폭포의 공중 낙하 구간 색으로 보기** — 빨강은 공중, 파랑은 지면을 타는 구간 (폭포) |
| **7** | **다른 폭포 자리** — 지형에서 찾은 후보를 차례로 돌려 본다 (폭포) |
| **8** | **폭포 앞으로 카메라 옮기기** — 물길은 지형에서 찾으므로 어디 생길지 미리 알 수 없다 (폭포) |
| ESC | 메뉴로 복귀 |

화면 왼쪽 아래에 **조작 안내 패널**이 떠서 어떤 키가 무엇을 바꾸는지, 지금 어떤 모드인지 보여준다.

### 터레인 에디터

터레인 쇼케이스의 조작(카메라 · Tab · T · O · G ...)은 그대로 쓰고, 아래가 더해진다.

| 입력 | 동작 |
| --- | --- |
| **마우스 이동** | 커서 아래 지형에 브러시 원이 붙어 따라다닌다 |
| **좌클릭 드래그** | 지형 칠하기 (에디터 패널 위에서 누른 클릭은 칠하지 않는다) |
| **1 / 2 / 3 / 4 / 5** | 올리기 / 내리기 / 평탄화 / 부드럽게 / 침식(원 안에만 물방울) |
| **R** | 수력 침식 한 번 실행 — 40만 방울을 떨어뜨리고 스스로 멈춘다. 실행 중에 누르면 멈춤 |
| **휠** (우클릭 없이) | 브러시 반경 |
| **[ / ]** | 브러시 세기 |
| F5 / F9 | 칠한 지형까지 저장 / 불러오기 (`Saves/scene.json` + `Saves/terrain_height_<id>.raw`) |
| N | 노이즈를 새 seed 로 다시 굽기 (칠한 내용은 사라진다) |

### 보강 — 약점 메우기

스텝 1~10 을 끝내고 나서 눈에 띈 약점 네 가지를 메웠다. 새 스텝을 만들지 않고 기존 스텝에 얹었으므로 **키 하나로 전후를 비교**할 수 있다.

| 약점 | 증상 | 보강 | 비교 키 | 상태 |
| --- | --- | --- | --- | --- |
| 절벽 텍스처 늘어짐 | UV 를 XZ 평면에서만 가져와 가파른 면에서 텍스처가 세로 줄무늬로 늘어진다. 청크마다 UV 가 0~1 이라 경계에서 무늬도 끊긴다 | 트라이플래너 매핑 | T | **완료** |
| 지형 끝이 보인다 | 무한 지형 가장자리에서 청크가 갑자기 생기고, 지형과 하늘의 경계가 칼로 자른 듯하다 | 거리 안개 · 대기 원근 | O | **완료** |
| 날아다니면 끊긴다 | 새 청크의 정점 계산을 메인 스레드가 해서 청크 경계를 넘는 프레임이 늦어진다 | 작업 스레드에서 계산, 메인 스레드는 버퍼만 생성 | B | **완료** |
| 땅속으로 들어간다 | 카메라가 지형을 몰라 산을 뚫고 지나가고, 걸어 다닐 수 없다 | 지면 높이 조회 · 걷기 모드 | G | **완료** |

측정 — 스텝 10 에서 4초 동안 앞으로 날며 조작 패널의 "메인 스레드 비용"(최근 0.5초 최댓값)을 읽었다 (Debug 빌드).

| 방식 | 메인 스레드 비용 |
| --- | --- |
| 메인 스레드에서 직접 생성 (B 끔, 프레임당 3개) | 4.99 ms |
| 작업 스레드 4개 + 메인은 업로드만 (B 켬) | 0.50 ms |

### 에디터 연결 — 엔진과 터레인 잇기

| 작업 | 내용 | 상태 |
| --- | --- | --- |

## 설계 메모

- **폭포 자리는 손이 아니라 지형이 정한다** — 좌표를 손으로 박아 두면 새 지형(N)이나 브러시 한 번에 물이 허공에 뜬다. 지형을 12 m 간격으로 훑어 "물 위로 높고 경사가 급한" 후보를 고른 뒤, 후보마다 물 한 덩이를 실제로 굴려 보고 공중 낙차가 가장 큰 물길을 고른다. 발원지 높이가 달라지면(새 지형 · 브러시 · 침식) 다시 찾는다.
- **물이 지면을 떠나는 순간이 곧 폭포다** — 물을 굴릴 때 중력을 경사면에 투영한 만큼 빨라지고 마찰로 느려지게 하면, 지면이 낙하보다 빨리 꺼지는 곳에서 자연히 물이 뜬다. 다만 노이즈 지형에는 수직 절벽이 거의 없어, 한 걸음(약 0.5 m) 사이에 지면이 15 cm 만 꺼져도 뜨게 잡아야 공중 구간이 생긴다. 처음엔 50 cm 로 잡아 공중 구간이 0 m 인 계류만 나왔다.
- **얇은 물은 깊이 페이드에 통째로 지워진다** — 물줄기는 지면에서 35 cm 위에 떠 있는 판이다. 수면(S77)처럼 "뒤 물체와 0.8 m 안이면 흐리게" 로 잡으면 비스듬히 볼 때 물줄기가 거의 사라진다. 0.2 m 로 줄여 지형과 맞닿는 선만 부드럽게 한다.
- **물보라는 정점 네 개로** — 물이 바닥을 때린 자리에 정점 네 개를 같은 점에 모아 두고 모서리 부호만 실어 보낸다. 펴는 일은 카메라의 오른쪽 · 위쪽 축을 아는 정점 셰이더가 한다. 씨앗마다 위상을 어긋나게 돌려 피어올랐다 사라지는 한살이를 만든다. 폭포 리본과 같은 메시 · 같은 셰이더라 그리기 호출이 늘지 않는다.

- **부딪힘은 격자가 아니라 입자로** — 클릭 물결(S79)은 높이 격자라 두 물결이 만나면 높이가 더해졌다 지나갈 뿐 힘이 깎이지 않았다. 격자에서 진행 방향을 알려면 높이 변화로 거꾸로 짐작해야 하는데, 예전에 그렇게 충돌을 판정한 시도(아래 "파도 충돌은 식이 아니라 스펙트럼으로")는 잡음까지 충돌로 잡았다. 입자는 방향을 들고 있어 "마주 오는가" 가 내적 하나로 정확히 나온다. 높이 텍스처는 그대로 두고 입자를 매 프레임 그 RTV 에 그리므로 수면 셰이더 · 진폭 창 · 높이 보기는 바뀌지 않았다. 입자는 월드 좌표에 있어 영역을 옮길 때 텍스처를 밀어 읽을 필요도 없어졌다(아래 두 원점 메모는 격자 시절 이야기다).
- **깎는 양은 입자 수와 무관해야 한다** — 고리는 커지면서 계속 셋으로 쪼개지므로 같은 물결도 입자 수가 바뀐다. 쌍 하나의 몫에 "상대 입자 간격 / 반경" 을 곱해 상대 고리 전체와 부딪힌 높이가 되게 하고, 정면으로 한 번 스쳐 가는 동안 합이 일정하도록 단계당 비율을 속도와 반경으로 정한다. 모든 쌍을 먼저 계산하고 한꺼번에 깎아야 검사 순서에 따라 결과가 달라지지 않는다.
- **빗방울은 입자 수를 폭발시킨다** — 감쇠를 모든 물결에 똑같이 주면 빗방울 고리도 수십 m 를 살아가며 계속 셋으로 쪼개져 입자가 상한까지 불어나고, 부딪힘 검사가 한 단계에 수십 ms 를 먹는다. 실제 물에서도 짧은 물결이 훨씬 빨리 사라지므로(점성 감쇠 ∝ 파수²) 반경에 따라 감쇠를 달리하고, 눈에 보이지 않을 만큼 낮은 고리는 부딪힘 격자에 넣지 않는다.
- **같은 물방울의 입자끼리는 깎지 않는다** — 막 퍼지기 시작한 고리는 반대편 입자끼리 겹쳐 있어 태어나자마자 서로 지워진다. 해안에서 반사된 자기 고리가 뒤따라오는 자기 고리와 만나 사라지면 반사도 보이지 않는다. 입자마다 고리 번호를 달아 다른 물방울의 물결끼리만 부딪히게 했다.
- **영역을 옮길 때 이전 · 현재는 원점이 다르다** — 물결 영역은 카메라를 따라 16 텍셀씩 옮긴다. 옮긴 직후 "현재" 텍스처는 한 칸 전 원점, "이전" 텍스처는 두 칸 전 원점에서 쓰였는데 둘을 같은 오프셋으로 읽고 있었다. 두 장이 16 텍셀 어긋나 "현재 - 이전" 이 엉뚱한 속도가 되고, 영역을 옮길 때마다 에너지가 생겨 클릭 한 번 뒤 카메라를 앞뒤로 움직이면 상한까지 폭주했다. 원점을 두 개 기억해 오프셋을 따로 넘긴다.
- **특정 각도의 회색 얼룩은 반사가 아니라 잡음이었다** — 반사 패스를 끄면 얼룩은 줄지만 원인은 물결 시뮬레이션이 상한(±8)에 걸려 생긴 체크무늬였다(진폭 창의 최대 진폭이 정확히 8.000). 이웃 평균 쪽으로 단계마다 2% 당겨 체크무늬를 없애고, 빗방울 세기를 1/4 로 줄이고, 수면 기울기를 약 30도에서 자르고, 프레넬은 위쪽으로 반쯤 평평하게 한 법선으로 계산해 한 픽셀만 하늘을 통째로 비추지 않게 했다.
- **파도 충돌은 식이 아니라 스펙트럼으로** — 클릭 물결 시뮬레이션(S79)에 "마주 오는 에너지 흐름을 감지해 거품과 손실을 더하는" 항을 붙여 봤지만, 격자 파동은 파장이 짧아 에너지가 조금만 모여도 충돌로 판정돼 화면 전체가 흰 거품으로 뒤덮였다. 실제 바다처럼 보이는 것은 개별 파도의 충돌이 아니라 스펙트럼의 파도들이 겹치며 마루가 접히는 곳(S86)이다. 그 방식으로 바꾸고 충돌 항은 걷어냈다.
- **거품은 촘촘한 타일에서만** — 800 m 타일은 텍셀 하나가 3 m 라 거기서 만든 거품은 수면 위에 회색 구름이 뜬 것처럼 번졌다. 거품은 71 m · 13 m 타일에서만 읽고, 무늬로 잘게 끊어 밝게 칠한다.
- **진폭 창은 D3D 와 GDI 가 나눠 그린다** — 텍스처 칸은 `RenderTransparent` 에서 D3D 로 그리고, 숫자 · 그래프는 그 뒤 GDI 오버레이에서 그린다. GDI 가 패널 배경을 통째로 칠하면 텍스처가 덮이므로 텍스처 칸을 뺀 둘레 네 조각만 칠한다. 레이아웃은 한 함수(`ComputeAmplitudeLayout`)에서만 계산해 두 단계가 같은 칸을 쓴다.
- **값은 0.1초마다, 기다리지 않고** — 512×512 실수(1MB)를 매 프레임 복사할 필요는 없다. 0.1초마다 복사를 부탁하고 결과가 도착한 프레임에만 통계를 새로 낸다. 커서가 움직이면 이미 받아 둔 값에서 단면과 커서 높이만 다시 고른다. 기록 그래프는 새 값이 도착했을 때만 한 칸 쌓는다.
- **물결은 RTV 핑퐁으로** — 컴퓨트 셰이더(S71)로도 되지만, 렌더 타깃 + 픽셀 셰이더로 같은 계산을 하는 방식이 D3D11 에서 더 오래되고 어디서나 동작한다. 한 단계는 "다음 텍스처를 렌더 타깃으로 걸고 → 화면 덮는 삼각형 한 개를 그리고 → 이름표를 한 칸 돌리기" 가 전부다. 끝나면 렌더 타깃과 SRV 를 모두 떼고 뷰포트를 되돌려 뒤따르는 메인 패스가 영향을 받지 않게 한다.
- **해안 벽은 물 위로 드러난 땅만** — 처음에는 수면보다 0.3 아래까지 땅으로 잡았는데, 그러면 물가에 떨어뜨린 물방울이 그 자리에서 바로 0 으로 눌려 사라졌다. 수면보다 높은 곳만 벽으로 두었다. 물결 높이 보기(1)에서 벽을 노랗게 칠해 마스크 방향과 위치가 지형과 맞는지 눈으로 확인할 수 있다.
- **해안 마스크는 나눠서 굽는다** — 128×128 점마다 지면 높이(노이즈)를 묻는 1만 6천 번의 질의를 한 프레임에 하면 멈춘다. 프레임당 6줄씩 굽고, 다 굽은 뒤 한 번에 GPU 로 올린다. 그동안은 이전 마스크를 쓴다. 물결 영역이 한 변의 10% 이상 옮겨졌거나 수위가 바뀌었을 때만 다시 굽는다.
- **물은 한 프레임에 씬을 두 번 그린다** — `Game::RenderScenePasses` 가 물이 있으면 반사 패스(불투명만)를 먼저 돌리고, 메인 패스에서 불투명 → 반투명 순으로 그린다. 컴포넌트는 `Graphics::GetRenderPass()` 로 지금 무엇을 그리는지 알 수 있고, 물은 반사 패스에서 자기 자신을 그리지 않는다. 지형 · 하늘 코드는 반사 패스를 전혀 모른다 — 뷰 행렬 · 눈 위치 · 자르기 평면만 Graphics 가 바꿔 끼운다.
- **깊이 버퍼는 형식 없이 만든다** — `D24_UNORM_S8_UINT` 텍스처는 깊이 버퍼로만 쓸 수 있다. `R24G8_TYPELESS` 로 만들면 같은 비트를 DSV 로는 깊이로, SRV 로는 0~1 실수로 볼 수 있다. 출력에 붙어 있는 동안은 읽을 수 없으므로 복사본을 읽고, 물을 그린 뒤 SRV 를 반드시 떼어 다음 프레임의 복사와 부딪히지 않게 한다.
- **자르기 거리는 출력 구조체의 맨 끝에** — `SV_ClipDistance0` 은 래스터라이저가 쓰고 픽셀 셰이더는 받지 않는다. 정점 출력과 픽셀 입력은 앞에서부터 순서가 맞아야 하므로 픽셀 셰이더가 안 쓰는 값은 맨 뒤에 둔다.
- **침식은 불변식으로 안정시킨다** — 계수만 줄이는 방법(높이 스케일 40 → 200)도 짧게는 버텼지만, 격자점당 46방울까지 돌리자 결국 -100억으로 발산했다. 대신 "각 격자점은 물방울이 흘러갈 높이보다 낮게 깎이지 않는다" 는 제한을 두면 구덩이가 스스로 깊어지는 고리 자체가 끊긴다. 수치 문제는 계수 조정보다 깨지면 안 되는 성질을 코드로 지키는 편이 확실하다.
- **침식은 한 번에 정해진 양만** — 끝없이 돌리면 흙이 가장자리로 계속 쓸려 나가 지형 전체가 평평해진다(재현에서 최고 높이 30 → -9.5). R 한 번에 40만 방울(격자점당 약 6방울)을 떨어뜨리고 스스로 멈추게 했다.
- **대량 재생성은 작업 스레드로, 묶음 단위로** — 침식은 매 프레임 거의 모든 청크를 바꾼다. 바뀐 청크가 12개를 넘으면 격자를 통째로 복사한 사본과 함께 작업 스레드에 넘기고, 그 묶음을 다 받기 전에는 다음 묶음을 보내지 않는다. 늦게 도착한 옛 결과가 새 결과를 덮어쓰지 않게 하려는 것이다. 브러시처럼 몇 개만 바뀌면 메인 스레드에서 바로 만든다.
- **바이옴 가중치는 정점에 싣는다** — 셰이더가 픽셀마다 기후 노이즈를 다시 계산할 수도 있지만, 그러면 CPU 높이 식과 GPU 색 식을 따로 맞춰야 한다. 정점 레이아웃에 `float4 biome` 하나를 더해(stride 48 → 64) CPU 가 계산한 값을 그대로 넘기면 한 곳에서만 정한다. 바이옴 경계는 수백 단위로 넓어 정점 간격(4)으로 보간해도 티가 나지 않는다. 입력 레이아웃에 셰이더가 안 쓰는 항목이 더 있어도 되므로 하늘 · 테셀레이션 셰이더는 고치지 않았다.
- **바이옴 경계에서 높이가 끊기지 않는 이유** — 네 바이옴의 높이를 각각 구한 뒤 가중치로 섞는다. 가중치가 공간에서 연속이면 섞인 높이도 연속이다. 사막(평평)과 설원(뾰족) 사이도 비탈로 이어진다.
- **바이옴은 노이즈 지형에서만** — 편집 격자는 이미 구운 높이라 기후를 바꿔도 값이 그대로이고, 스텝 7 의 GPU 생성 셰이더는 바이옴 식을 옮기지 않았다. 둘 다 가중치를 "전부 초원" 으로 둔다.
- **GPU 노이즈는 CPU 식을 그대로 옮긴다** — 해시의 정수 곱셈 · xor · 시프트는 HLSL `uint` 에서도 32비트로 감기므로 C++ `unsigned` 와 결과가 같다. 그래서 GPU 로 만든 높이 텍스처와 CPU 의 `HeightField::Sample` 이 일치하고(높이 범위가 소수 둘째 자리까지 같다), 카메라 지면 질의는 CPU 함수를 그대로 쓴다.
- **쓰기 뷰는 다 쓰면 뗀다** — 높이 텍스처는 컴퓨트 셰이더가 UAV 로 쓰고 도메인 셰이더가 SRV 로 읽는다. 둘이 동시에 붙어 있으면 D3D 가 읽기 쪽을 조용히 떼어 버려 지형이 평면이 된다. `Dispatch` 뒤에 `CSSetUnorderedAccessViews(nullptr)` 로 반드시 해제한다. 테셀레이션 단계를 해제하는 것과 같은 규칙이다.
- **GPU 시간은 기다려서 잰다** — `Dispatch` 는 명령을 올리고 바로 돌아오므로 그 직후에 재면 거의 0 이다. 텍셀 하나를 스테이징으로 복사해 `Map` 하면 GPU 가 거기까지 끝낼 때까지 막히므로 그 시점까지를 계산 시간으로 본다. 첫 `Dispatch` 는 드라이버 준비 시간이 섞여(90ms) 한 번 미리 돌려 두고 잰다.
- **편집하려면 함수를 표본으로 굽는다** — 에디터 씬은 노이즈를 257×257 `HeightGrid` 에 한 번 굽고 높이 공급원을 `HeightSource::Grid` 로 바꾼다. 청크 생성 · 법선 · 지면 질의 · 피킹은 모두 `HeightField::Sample` 을 거치므로 코드를 하나도 바꾸지 않고 편집한 높이를 쓴다. 격자점은 정점과 같은 자리에 있어 정점 높이가 보간 없이 그대로 나온다.
- **재생성은 표시만 하고 한 번에** — 브러시는 한 프레임에 여러 번 영역을 알릴 수 있다. `MarkRegionDirty` 는 겹치는 청크에 표시만 하고, `Update` 에서 표시된 청크를 한 번씩만 다시 만든다. 정점 법선이 이웃 칸 높이로 계산되므로 영역을 한 칸 넓혀야 경계에 조명 이음매가 생기지 않는다.
- **편집 지형은 무한 모드로 가지 않는다** — 격자는 크기가 정해진 표본이라 무한히 이어 붙일 수 없고(스텝 3 의 이미지와 같은 이유), 무한 지형은 작업 스레드가 높이를 읽으므로 브러시가 동시에 고치면 데이터 경쟁이다. `SetInfiniteEnabled` 가 편집 중이면 거절한다.
- **UI 위의 마우스는 게임이 양보한다** — `Game` 이 매 프레임 패널 영역을 보고 `InputManager::SetPointerOverUI` 로 알려 주고, 브러시는 그 값만 본다. 브러시가 에디터 패널 클래스를 알 필요가 없다. 칠하기는 "누른 순간 지형 위였을 때" 만 시작하므로 패널에서 누르고 끌고 나와도 칠해지지 않는다.
- **한 프레임 안의 누름과 뗌을 나눠 반영한다** — 프레임이 느린 씬(에디터)에서 키를 톡 치면 `WM_KEYDOWN` 과 `WM_KEYUP` 이 같은 프레임에 들어온다. 둘을 한꺼번에 반영하면 상태가 Down 을 건너뛰고 Up 이 되어 `GetKeyDown` 이 한 번도 참이 되지 않았다(브러시 도구 키가 가끔 안 먹던 원인). 이제 하나만 이번 프레임에 반영하고 나머지는 다음 프레임으로 넘긴다.
- **청크 지형도 저장된다** — 예전에는 `ChunkedTerrainRenderer` 에 `ToJson` 이 없어 F9 로 불러오면 기본 설정 지형이 나왔다. 격자 크기 · 노이즈 설정 · 표시 모드 · 토글을 저장하고, 편집 격자는 이진 파일 경로로 남긴다.
- **안개는 하늘이 켠다** — 안개는 지형이 아니라 공기의 성질이다. `SkyRenderer` 가 Update 에서 `Graphics::SetFog` 로 켜고 `Graphics::EndFrame` 이 끈다. 하늘이 없는 씬(스텝 1~6)으로 넘어가면 다음 프레임에 아무도 켜지 않으므로 안개가 남지 않는다. 지형 렌더러는 안개가 있는지조차 모른다.
- **스레드 경계는 "순수 계산" 에서 자른다** — 작업 스레드는 `ChunkMeshData`(정점·인덱스 벡터)까지만 만들고, `ID3D11Buffer` 생성과 슬롯 교체는 메인 스레드가 한다. 잠금이 필요한 곳이 요청 큐와 결과 큐 두 군데뿐이라 교착을 걱정할 일이 없고, 무거운 계산은 잠금 밖에서 한다.
- **높이 함수는 사본을 넘긴다** — N 키로 지형을 다시 만들면 메인 스레드가 `HeightField` 를 바꾼다. 작업 스레드가 같은 객체를 읽는 중이면 데이터 경쟁이다. 재생성할 때마다 `shared_ptr<const HeightField>` 사본을 만들어 요청에 실어 보낸다.
- **주문 장부로 중복을 막는다** — 매 프레임 "필요한데 없는 청크" 를 모으면 이미 주문한 것도 다시 잡힌다. 주문한 좌표를 `m_inFlight` 에 적어 두고 결과를 받거나 취소했을 때만 지운다. 카메라가 청크 경계를 넘으면 아직 시작하지 않은 요청은 거둬들이고 새 거리 순서로 다시 줄 세운다.
- **카메라는 지형을 모른다** — `Camera` 는 씬의 컴포넌트 중 `IGroundProvider` 를 구현한 것만 찾는다. 스텝 1~4 / 5~10 / 7 의 렌더러가 모두 다르지만 카메라 코드는 하나다. 씬 구성 코드에서 포인터로 연결하지 않으므로 F9 로 씬을 다시 불러와도 끊어지지 않는다.
- **조작 패널은 글자 폭을 재서 열을 맞춘다** — 보강 키가 늘면서 "백그라운드 생성" 같은 긴 설명이 값과 겹쳤다. 고정 좌표 대신 그릴 때 `GetTextExtentPoint32W` 로 가장 긴 설명·값의 픽셀 폭을 재서 열 위치와 패널 폭을 정한다.
- **셰이더 캐시는 include 파일도 본다** — `TerrainCommon.hlsli` / `Atmosphere.hlsli` 만 고치고 `.hlsl` 은 그대로면, `.hlsl` 시각만 비교하는 캐시는 낡은 `.cso` 를 계속 쓴다. 그래서 `Shaders` 폴더의 `.hlsli` 중 가장 최근 수정 시각보다도 `.cso` 가 새로울 때만 캐시를 쓴다.
- **입력** — Win32 메시지는 pending 큐에 쌓고 `InputManager::Update()` 에서 한 번에 반영한다. 그래서 "메시지 처리 → 입력 갱신" 순서에서도 Down/Up 이 정확히 한 프레임만 참이다.
- **Transform** — 로컬 값이나 부모 관계가 바뀔 때만 Dirty 를 세우고 자식에게 전파한다. 재부모화는 기존 월드 행렬과 새 부모의 역행렬로 로컬을 구해 `XMMatrixDecompose` 로 분해한다.
- **지연 변경** — Component 추가/삭제, GameObject 생성/삭제 모두 큐를 거쳐 프레임 끝에서만 컨테이너를 수정한다. 씬 전체를 갈아엎는 `Scene::Load` 는 렌더까지 끝난 뒤 `Game::HandleFrameEndCommands()` 에서 실행한다.
- **Shader Hot Reload** — 새 리소스를 임시로 전부 만든 뒤 모두 성공했을 때만 교체한다. 실패하면 마지막 성공 셰이더를 계속 쓰므로 화면이 깨지지 않는다. Release 빌드에서는 `std::filesystem` 감시 코드가 컴파일에서 제외된다.
- **JSON** — 외부 라이브러리 없이 `Utils/Json` 에 파서와 직렬화기를 직접 구현했다. 객체는 삽입 순서를 유지하고, 위치/회전/스케일 같은 짧은 숫자 배열은 한 줄로 출력한다.
- **에셋 폴백** — 이미지 파일을 찾지 못하면 체커보드 텍스처를 만들어 실행이 멈추지 않게 한다.
- **피킹** — `Graphics::ScreenToWorld`가 마우스 클라이언트 좌표를 NDC로 바꾼 뒤 `View * Projection`의 역행렬로 월드 좌표를 구한다. 직교 투영이라 x·y는 깊이와 무관하므로 z=0 평면의 점으로 다룬다. `SpriteRenderer::HitTest`는 그 점을 **월드 행렬의 역행렬**로 스프라이트 로컬 공간에 되돌려 Quad 범위와 비교하므로 회전·스케일·부모 변환이 모두 반영된다. 겹치면 나중에 그려진 쪽이 선택된다.
- **선택 하이라이트** — 같은 Quad를 외곽선 두께만큼 크게, 텍스처의 알파만 쓰는 단색 실루엣으로 먼저 그리고 그 위에 원본을 겹친다(`gParams.x`로 픽셀 셰이더 분기). 깊이 버퍼 없이 화가 알고리즘만으로 외곽선이 된다.
- **선택 상태는 ID로 보관** — `Game`은 선택된 오브젝트를 포인터가 아니라 `uint64_t` ID로 들고 있다. 선택한 오브젝트를 F2로 삭제하거나 F9로 씬을 다시 로드해도 잘못된 포인터를 쓰지 않는다.
- **드래그 이동** — 버튼을 누른 순간 `오브젝트 월드 위치 - 커서 월드 위치`를 저장해 두고, 매 프레임 커서 위치에 그 차이를 더한다. 잡은 지점이 튀지 않는다. 목표 월드 위치는 `Transform::SetWorldPosition`이 **부모 월드의 역행렬**로 되돌려 로컬 위치로 바꾸므로, 부모가 회전·확대되어 있어도 자식이 커서를 정확히 따라간다. `SetWorldMatrix`와 달리 분해(decompose)를 하지 않아 회전·스케일에 오차가 쌓이지 않는다.
- **드래그는 계층을 건드리지 않는다** — 그냥 드래그하면 부모-자식 관계가 그대로 유지된다(에디터의 일반적인 동작). 자식으로 남아 있으므로 이후 부모가 회전·이동하면 함께 끌려가는데, 이는 계층 구조상 맞는 동작이다.
- **계층 변경은 Hierarchy 패널에서만** — 씬 드래그는 이동 전용이고, 부모를 바꾸는 것은 Hierarchy에서 줄을 끌어다 놓을 때뿐이다. 되돌릴 수 없는 조작을 우연히 일으키지 않게 분리했다. 재부모화는 `SetParent(newParent, worldPositionStays: true)`라 화면에 보이는 위치·회전·크기가 그대로 유지된다.
- **에디터 UI는 GDI 오버레이** — 백버퍼를 `DXGI_FORMAT_B8G8R8A8_UNORM` + `DXGI_SWAP_CHAIN_FLAG_GDI_COMPATIBLE`로 만들고 `IDXGISurface1::GetDC`로 DC를 빌려 씬 위에 직접 그린다. 폰트 텍스처나 텍스트 렌더링 파이프라인이 따로 필요 없고 한글 이름도 그대로 나온다. DC는 프레임당 한 번만 잡아 두 패널이 나눠 쓴다.
- **메인 메뉴도 하나의 씬** — `Scene` 을 상속하지 않는다. `MainMenu` 씬에 `MenuRoot` 오브젝트를 두고 `MenuController` 컴포넌트를 붙일 뿐이다. 이 엔진의 확장 방식이 상속이 아니라 합성이기 때문이다. 덕분에 `AppState` 같은 분기가 사라지고 게임 루프가 한 갈래로 통일됐다. 메뉴 배경에 지형이나 스프라이트를 띄우고 싶으면 GameObject 를 더하면 된다.
- **씬 전환은 프레임 끝에** — 메뉴 항목을 고른 그 자리에서 씬을 바꾸면 지금 `Update` 를 돌고 있는 `MenuController` 자신이 파괴된다. 그래서 선택은 콜백으로 **요청만 남기고**(`RequestScene`), 실제 전환은 렌더까지 끝난 뒤 `ProcessPendingSceneChange` 에서 한다. `Scene::Load` 를 프레임 끝으로 미룬 것과 같은 이유다.
- **오버레이 DC 는 프레임당 하나** — GDI 오버레이는 `Graphics::BeginOverlay` 로 한 번만 잡고 메뉴·Hierarchy·Inspector 가 나눠 쓴다. 그래서 `MenuController` 는 `Render()` 가 아니라 `DrawOverlay(hdc)` 를 통해 그린다.
- **메뉴는 데이터 기반** — 항목을 `{ 제목, 설명, 씬 구성 람다 }` 목록(`m_showcases`)으로 들고 있고 메뉴 화면은 그 목록을 그릴 뿐이다. 스텝이 늘어나면 `Game::SetupMenu()` 에 `push_back` 한 줄만 더하면 된다. 분기문(`if index == 0`)이 없으므로 항목이 늘어도 진입 코드는 그대로다.
- **카메라는 Transform 을 소유한다** — 위치와 yaw/pitch 를 **매 프레임 자기 GameObject 의 Transform 에 써 넣는다.** 그래서 Inspector 에 실제 카메라 위치가 보인다. 반대로 Inspector 에서 값을 고치면, 마지막으로 써 넣은 값과 달라진 것을 감지해 카메라 상태로 되받는다(양방향 동기화).
- **상하만 제한하는 이유** — yaw 는 얼마든지 돌아도 되지만 pitch 가 ±90도를 넘으면 화면이 뒤집힌다. 게다가 **정확히 ±90도에서는 보는 방향이 up 벡터(0,1,0)와 평행해져 뷰 행렬을 만들 수 없다.** 그래서 89.9도로 자른다. 한계까지 밀어붙였다가 되돌려도 행렬이 깨지지 않는다.
- **우클릭을 카메라에 넘겼다** — 예전에는 우클릭이 선택 해제였다. 카메라 프리룩과 겹치므로 선택 해제는 "빈 곳 좌클릭" 하나로 통일했다.
- **`LookTo` vs `LookAt`** — 궤도 카메라는 한 점을 바라보므로 `XMMatrixLookAtLH`, 프리룩 카메라는 방향을 바라보므로 `XMMatrixLookToLH` 가 맞다. 씬 초기 배치용으로만 `Camera::LookAt(target)` 을 두어 위치에서 각도를 역산한다.
- **테셀레이션 단계는 반드시 해제한다** — `HSSetShader`/`DSSetShader` 는 한 번 설정하면 계속 남는다. 패치를 그린 뒤 `nullptr` 로 되돌리지 않으면, 다음에 삼각형 목록을 그리는 하늘·UI 가 깨진다. `Shader::Bind` 도 테셀레이션이 없으면 명시적으로 `nullptr` 을 넣는다.
- **분할 계수는 변의 중점으로 계산한다** — 패치마다 제멋대로 정하면 경계에 틈이 생긴다. 두 패치가 공유하는 변은 중점도 같으므로, 중점까지의 거리로 계산하면 양쪽이 반드시 같은 값을 얻는다.
- **무한 지형에서는 쿼드트리를 쓰지 않는다** — 청크가 매 프레임 움직이면 트리를 다시 세워야 해서 이득이 사라진다. 청크 수가 수백 개 수준이라 하나씩 절두체 검사를 해도 충분하다. 자료구조는 상황에 맞게 고르는 것이지 항상 좋은 것이 있는 게 아니다.
- **메뉴는 스크롤한다** — 항목이 늘어나도 화면을 넘치지 않도록, 들어가는 개수만 그리고 나머지는 굴려서 본다. 선택이 화면 밖으로 나가면 따라 스크롤한다.
- **마우스는 움직였을 때만 선택을 가져간다** — 예전에는 커서 아래 항목을 매 프레임 선택으로 덮어써서, 커서가 메뉴 위에 가만히 있으면 ↑↓ 로 바꾼 선택이 다음 프레임에 되돌아갔다(씬에서 ESC 로 돌아온 직전 커서 위치가 항목 위면 키보드가 먹히지 않았다). 직전 프레임과 좌표가 달라진 프레임에만 호버를 선택으로 옮긴다.
- **색상 램프는 지형 전체 기준으로** — 청크마다 자기 min/max 로 높이를 정규화하면 평평한 청크에도 눈이 덮인다. 정규화 기준은 반드시 지형 전체의 최저/최고 높이여야 한다.
- **하늘은 정점 형식을 재사용한다** — 하늘 돔은 POSITION 과 방향만 쓰지만 터레인 정점 형식을 그대로 쓴다. 입력 레이아웃에 셰이더가 안 쓰는 항목이 더 있는 것은 허용되므로, 형식을 하나 더 만들 이유가 없다.
- **모프 타깃 4개를 정점에 담는다** — LOD 마다 "다음 단계에서 이 정점이 가질 높이" 가 다르다. 4개를 `float4` 한 개로 정점에 넣어 두고, 셰이더에서 현재 LOD 성분만 1 인 `gLodSelect` 와 내적해 하나를 고른다. 분기 없이 값 하나를 뽑는 흔한 수법이다.
- **스커트 때문에 컬링을 껐다** — 스커트는 테두리를 아래로 내려뜨린 벽이라 앞뒤 방향을 따지기 번거롭다. 지형은 하이트필드라 뒷면 컬링으로 걸러지는 양도 적어서, 아예 `CULL_NONE` 으로 두고 스커트 winding 을 신경 쓰지 않기로 했다.
- **정점은 한 벌, 인덱스는 여러 벌** — LOD 마다 정점 버퍼를 따로 두면 메모리가 4배로 는다. 청크는 가장 촘촘한 정점 한 벌만 두고, LOD 별 인덱스를 **하나의 인덱스 버퍼에 이어 붙인 뒤 구간(offset, count)만 바꿔** 그린다.
- **스텝 1~4 와 5~ 는 렌더러가 다르다** — 스텝 1~4 는 지형이 메시 한 덩어리(`TerrainRenderer`)고, 스텝 5 부터는 청크 기반(`ChunkedTerrainRenderer`)이다. "한 덩어리의 한계" 를 보여주는 것이 스텝 1~4 의 목적이므로 억지로 합치지 않았다.
- **보기 방식은 키 하나로** — 와이어프레임·높이 색상·스플래팅·평면은 서로 배타적인 "보기 방식" 이라 별개의 토글 키로 두면 조합이 꼬인다. `DisplayMode` 하나로 묶고 Tab 으로 순환한다. 상태가 하나뿐이라 잘못된 조합(예: 와이어프레임 + 스플래팅)이 아예 생기지 않는다.
- **조작은 화면에 적어 둔다** — 키를 외우게 하지 않는다. `ControlsPanel` 이 현재 씬에 있는 조작만 골라 보여주고, 지금 상태(표시 모드·노이즈 종류)를 값으로 함께 띄운다.
- **스플래팅 가중치는 셰이더에서** — 스플랫맵 텍스처를 따로 굽지 않고 높이와 경사도로 매 픽셀 계산한다. 지형을 새로 생성해도(N 키) 텍스처를 다시 만들 필요가 없다. 대신 지형 상태와 정확히 일치하는 대가로 아티스트가 손으로 칠할 수는 없다 — 그게 필요하면 스플랫맵 방식으로 간다.
- **레이어 4장을 t0~t3 에 한 번에** — `MeshDrawParams::layers` 배열을 `PSSetShaderResources(0, 4, ...)` 로 통째로 바인딩한다. 와이어프레임일 때는 의미가 없으므로 스플래팅을 끈다.
- **높이 공급원도 갈아 끼울 수 있게** — `HeightParams::source` 하나로 노이즈/이미지를 고른다. `Sample()` 한 곳에서만 갈라지므로 `SampleNormal` 은 손댈 필요가 없다 — 법선은 어느 쪽이든 같은 중앙 차분으로 나온다. 스텝 1(평면) · 2(노이즈) · 3(이미지)이 같은 `TerrainRenderer` 를 쓰고 `TerrainMode` 만 다르다.
- **WIC 로더를 공유** — `Texture`(GPU 업로드)와 `HeightMapImage`(CPU 높이 읽기)가 같은 이미지 로딩 경로를 쓴다. WIC 팩토리를 두 벌 만들지 않고 `Graphics/WicLoader` 한곳에 모았다.
- **노이즈는 갈아 끼울 수 있게** — `HeightParams::noiseType` 하나로 펄린/값 노이즈를 고른다. fBm 은 어느 쪽이든 그대로 얹히므로 `BaseNoise()` 한 곳만 분기한다. 알고리즘 차이를 실행 중에 눈으로 비교할 수 있어야 왜 펄린을 쓰는지 납득이 된다.
- **fade 곡선을 따로 쓴 이유** — 값 노이즈는 `smoothstep`(3t²-2t³), 펄린은 `6t⁵-15t⁴+10t³` 을 쓴다. 후자는 2차 미분까지 0 이라 격자 경계에서 **법선이 튀지 않는다.** 터레인처럼 기울기로 조명을 계산하면 이 차이가 눈에 보인다.
- **높이와 법선은 같은 함수에서** — 정점의 y 는 `HeightField::Sample`, 법선은 같은 함수를 좌우/앞뒤로 한 칸씩 샘플링한 중앙 차분으로 구한다. 삼각형 면법선을 모아 평균 내는 방식보다 코드가 짧고 이음매가 매끄럽다.
- **2D 와 3D 를 한 프레임에** — `Graphics` 가 직교(스프라이트)와 원근(터레인) 두 벌의 View/Projection 을 따로 들고 있다. 스프라이트는 깊이 테스트를 끄고 그린 순서대로, 메시는 깊이 테스트를 켜고 그린다. 덕분에 기존 2D 경로를 건드리지 않고 3D 를 얹었다.
- **카메라는 컴포넌트** — `Camera` 가 Update 에서 View/Projection 을 계산해 `Graphics::SetCamera3D` 로 넘긴다. 모든 Update 가 끝난 뒤 Render 가 돌기 때문에 같은 프레임 안에서 순서가 보장된다.
- **격자선은 텍스처가 아니라 픽셀 셰이더로** — UV 에 칸 수를 곱하고 `frac`/`fwidth` 로 셀 경계를 찾는다. 텍스처 로딩 없이 10칸마다 굵은 선까지 그릴 수 있고, 카메라가 멀어져도 선 굵기가 일정하다.
- **메시 재생성은 Dirty 일 때만** — `TerrainRenderer` 는 격자 설정이 바뀐 프레임에만 정점 버퍼를 다시 만든다. Transform 의 Dirty Flag 와 같은 규칙이다.
- **텍스트 입력 캡처** — 인스펙터가 글자를 받는 동안 `InputManager::SetTextCaptureActive(true)`로 게임 쪽 키 조회를 막는다. 이름에 'D'를 쳐도 캐릭터가 움직이지 않는다. Enter·Backspace·Esc는 `WM_CHAR`로 함께 들어오므로 편집 중 Esc는 취소, 편집이 아닐 때 Esc는 종료로 갈린다.
